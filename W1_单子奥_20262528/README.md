完成情况对应作业的三条要求：

1. **读取并检查**：`imread_checked()` 在解码失败时抛异常（而不是让后续代码拿到 `None` 崩在别处），
   并打印“宽 / 高 / 通道数 / dtype”，例如 `宽=640 高=480 通道数=3 dtype=uint8`。
2. **缩放 / 裁剪 / 灰度**：`cv2.resize(fx=0.5, fy=0.5, INTER_AREA)`；
   裁剪用切片 `img[y0:y1, x0:x1]`，坐标按比例算出（中心 60% 区域，x∈[128,512]、y∈[96,384]）；
   `cv2.cvtColor(..., COLOR_BGR2GRAY)` 得到单通道图。三者都落盘并汇总成四联对比图。
3. **保存后校验**：`save_and_verify()` 写完后立刻用 `imgio.imread` 重新读回来，比对 `shape` 是否一致；
   另外在运行前后对 `images/` 里每个文件算 sha256，**证明原始图片没有被覆盖**（日志最后一行）。

`outputs/task1/task1_log.txt` 是完整运行记录，每张图 4 个输出文件加 1 条校验信息。

关于 BGR 与 RGB：OpenCV 的 `imread` 默认按 **BGR** 顺序存通道（`img[:,:,0]` 是蓝），
而 matplotlib / PIL 按 RGB。本作业全程在 OpenCV 内部处理，只在需要和外部库交换数据时才
`cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`，否则会出现“红蓝互换”。

## 5. 任务二：预处理参数对比（一张图，单变量）

输入：`images/03_orange_clutter.jpg`（640×480，米色纹理背景 + 橙色目标 + 两个干扰物）。
输出：`outputs/task2/` 下 11 张中间结果 + `11_compare_grid.png` 汇总图 + `task2_stats.txt` 指标表。
所有指标都是从代码里实测打印的，不是目测估计。

| 操作 | 参数 | 客观指标 | 观察到的变化 |
| --- | --- | --- | --- |
| 灰度 | — | 均值 194.7，p10/p50/p90 = 196/201/205 | 图像整体偏亮，目标和背景灰度差约 50 |
| 高斯滤波 | k=3 / k=9 | Laplacian 方差：原图 29.3 → 7.2 → 1.7 | 核越大高频细节越少；k=9 时背景纹理基本磨平，目标边缘也变软 |
| 固定阈值（偏低） | T=120 | 前景 2.96%，连通域 2 | 只切出了两个较暗的干扰物，**橙色目标（灰度≈145）整个被漏掉** |
| 固定阈值（偏高） | T=195 | 前景 9.78%，连通域 **1486** | 背景纹理和噪声也被切成前景，出现大量碎点 |
| Otsu 自适应阈值 | 自动得 158 | 前景 7.39%，连通域 3 | 不用手调，阈值落在目标与背景之间，效果接近 T=170 左右 |
| Canny 边缘 | (5, 20) / (100, 200) | 边缘像素 3391 / 1047 | 阈值过低时噪声形成大量伪边缘；提高到 (100,200) 只剩目标轮廓 |
| 开运算 | 5×5 | 连通域 1486 → 3 | 去掉碎点，目标区域保留 |
| 闭运算 | 7×7（接开运算后） | 连通域 3，前景 7.69% | 补掉目标内部的小孔，轮廓更连续 |

结论（至少两条参数的影响，对应作业要求）：

1. **高斯核大小**决定平滑强度：Laplacian 方差从 29.3 降到 1.7，噪声被压掉的同时边缘也变模糊，
   后续若要 Canny，k=3~5 比 k=9 更合适。
2. **阈值高低**直接决定前景多少：T=120 漏掉目标（前景仅 2.96%），T=195 把背景纹理全切进来
   （连通域 1486 个）。所以阈值应该取在目标灰度与背景灰度之间，这也是后面任务三改用
   HSV 颜色阈值、而不是灰度阈值的原因。
3. **Canny 双阈值**：低了会把噪声当边缘（3391 vs 1047 个像素），高了会断开弱边缘，
   一般配合轻度高斯滤波使用。
4. **开运算 / 闭运算**：开运算对“背景碎点”最有效（连通域 1486 → 3），闭运算负责补内部小孔，
   顺序上先开后闭。

## 6. 任务三：颜色目标提取 + 轮廓定位

对 `images/` 下 4 张图分别执行：`BGR→HSV` → `inRange` 掩膜 → 开/闭运算 → `findContours`
→ 按面积过滤 → 取最大轮廓 → 算中心点、面积、外接矩形 → 在原图上标注并保存。

### 6.1 HSV 范围是怎么定的

| 颜色 | 下限 (H,S,V) | 上限 (H,S,V) | 依据 |
| --- | --- | --- | --- |
| 蓝色 | (100, 120, 70) | (130, 255, 255) | 目标区域实测 H≈108、S≈222、V≈229；H 取 ±15 覆盖明暗变化，S≥120 排除灰白背景，V≥70 排除阴影 |
| 绿色 | (40, 90, 60) | (85, 255, 255) | 实测 H≈56、S≈193、V≈140；绿色在 HSV 里跨度较大，H 取 40~85 |
| 橙色 | (8, 120, 80) | (25, 255, 255) | 实测 H≈13、S≈228、V≈240；橙色和黄色/红色相邻，H 上限收到 25 避免误检偏红区域 |

规则是：**H 定颜色种类，S 下限滤掉灰白（无彩色）背景，V 下限滤掉过暗像素**。
范围没有取到 0~255 的理论边界，而是留了余量，因为 JPEG 压缩、光照会让颜色在 H/S/V 上漂移。

### 6.2 面积阈值

`MIN_AREA_RATIO = 0.002`，即图像面积的 0.2%：640×480 × 0.2% ≈ **614 px**。
依据是目标实际面积在 1.3 万~2.5 万像素之间，而背景噪点连通域通常只有几十到几百像素，
614 px 既能把碎点全部滤掉，又不会误伤远处/较小的真实目标。

### 6.4 稳定 / 失败场景

- **稳定**：背景颜色和目标差异大（蓝圆在浅灰背景、绿块在暗背景）；目标亮度和饱和度足够；
  干扰物（灰色、蓝色）与目标色相不同，被 H 范围直接排除——03 图里的灰色圆和蓝色小圆都没有误检。
- **容易失败**：
  1. **低照度**：04 图目标 V 中位数只有 67，低于 `V≥80` 的下限 → 掩膜全空 → 漏检；
  2. **目标与背景色相接近**（例如橙目标 + 米色背景）时，H 区间必须收窄，否则掩膜连成一片；
  3. **遮挡**会让最大轮廓面积骤减，可能被面积阈值误杀；
  4. 面积阈值是固定比例，远距离小目标会被过滤掉。

## 7. 失败案例与改进思路

**失败案例：04_hard_lowlight.jpg 漏检（已复现并自动记录）**

- 现象：`[04_hard_lowlight.jpg] 未检出目标（轮廓 0 个，面积过滤后 0 个）`。
- 原因：图像整体欠曝，目标 HSV 实测 `H≈16, S≈202, V≈67`，而橙色范围要求 `V≥80`，
  于是 `inRange` 直接返回全黑掩膜，`findContours` 找不到任何轮廓。
- 改进：把 V 下限从 80 降到 40 再跑一次，即可检出 `center=(349, 249) area=10637`，
  结果保存为 `outputs/task3/04_hard_lowlight/result_relaxed.png`（`task3_color.py` 里
  `RELAXED_MIN_V=40` 就是这段兜底逻辑，同时会写进 `results.csv` 的 note 列）。
- 思路：真实场景里不应该把 V 下限写死，常见做法是 **先用 Otsu/直方图估计亮度水平再动态放宽**，
  或者在摄像头端做自动曝光；另一种是把颜色判断换到 `Lab`/`YCrCb` 空间，对亮度变化更鲁棒。

其他踩过的问题（都已在代码里解决，保留在这里作为记录）：

1. **Windows 中文路径**：提交文件夹名是 `W1_单子奥_20262528`，而 `cv2.imread/imwrite`
   走 ANSI 文件接口，遇到中文路径会 `imread` 返回 `None`、`imwrite` 返回 `False` 但不报错。
   解决：`src/imgio.py` 用 `np.fromfile` + `cv2.imdecode` 读、`cv2.imencode` + `tofile` 写，
   对中文路径/英文路径都正常。这个问题在第一次运行时直接导致“读不到图片”，排查后才定位到。
2. **只看白色像素占比会掩盖参数差异**：任务二最初用“前景像素占比”衡量阈值效果，
   背景面积占 97%，T=80 和 T=140 的数值只差 1.8 个百分点，看不出问题。
   改成同时统计 **连通域个数** 后，阈值偏高导致 1486 个碎点的问题才暴露出来。
3. **Canny 边缘计数对阈值不敏感**：目标边缘本来就强，双阈值在 20~150 之间变化时边缘像素数几乎不变
   （1036）。改用低阈值 (5,20) 并去掉预滤波，噪声伪边缘才显现（3391 vs 1047），对比才有意义。
4. **形态学要在“干净的图”上才能量化**：开运算在 T=120 的二值图上几乎没有变化，
   只有作用在 T=195 这种带大量碎点的图上，才能观察到连通域 1486 → 3 的效果。
5. **选做摄像头在无摄像头机器上会卡住**：`cv2.VideoCapture(0)` 打不开时给出提示，
   并支持 `--video <文件>` 用视频文件跑完整流程（已用 20 帧合成视频验证通过，约 300 FPS）。

## 11. 已知局限

- 颜色阈值是**固定写死**的，换场景需要重新调参；没有做白平衡/曝光补偿。
- 只取**面积最大的一个轮廓**，多目标场景只输出一个结果（扩展方向：对每个满足面积阈值的轮廓都输出）。
- 面积阈值用固定比例，远距离小目标会被误过滤（改进：按目标像素尺度或结合 `minAreaRect` 长宽比）。
- 未做相机标定与像素→物理坐标换算，因此只给出图像坐标 `(x,y)`，不具备机器人控制所需的实际坐标。
